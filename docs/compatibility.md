# Installation compatibility

The plugin keeps the technical identifiers used by its earlier internal development builds.
They identify an installed background service, its files and theme data; they are not a separate
product dependency.

| Identifier | Purpose |
| --- | --- |
| `bogen.portrait-background` | Plugin id, installation folder and source marker |
| `bogen.plugin: "portrait-background"` | Ownership mark in the installed manifest |
| `~/.local/state/bogen/portrait-background/` | Installer state and backups |
| `~/.cache/bogen/portrait-background/` | Verified image cache |
| `"kind": "bogen-portrait-runtime"` | Theme manifest format |

Changing these identifiers would disconnect existing local installations and theme manifests.
The installer recognizes earlier generated installations through their plugin id and ownership
mark, detects outdated versions and backs up files before replacing them. Hand edits require
`--force`. Updates and rollback use the same backup layout.

## Runtime source and versions

The canonical runtime is `plugin/PortraitMapping.qml`, `plugin/PortraitRuntime.js` and
`patch/background-patch.json`. The patch specification's `pluginVersion` and the runtime version
reported by PortraitMapping.qml must agree. Change runtime files here first and vendor pinned
copies in dependent projects; do not fetch code dynamically at build or run time.

Versions through 1.0.2 were internal development builds. Version 1.0.3 keeps patch 1 and the same
data contract, adds subprocess deadlines and improves the standalone installer.

The marketplace snapshot is generated by `tools/prepare-marketplace.py`. End-user installations
always derive Background.qml from that user's installed Omarchy, rather than the review snapshot.
